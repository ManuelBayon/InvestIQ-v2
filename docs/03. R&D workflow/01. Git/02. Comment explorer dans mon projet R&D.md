
Pour les phases d'exploration suivre la méthode suivante.

---
## 1. Une branche d'exploration

Par exemple : `explore/decision-trigger-semantics` 

>[!warning]
>A la fin ne pas faire : `merge explore/decision-trigger-semantics`

Je n’ai pas besoin que les commits soient parfaits, mais ils doivent quand même raconter suffisamment ce que je teste.

```
try emitted-feature readiness
test initialized-state alternative
prototype trigger policy abstraction
compare multi-timeframe behavior
```

Et avant de basculer vers l’implémentation propre, faire un mini checkpoint :

```
Question
Hypothèses testées
Résultat
Décision retenue
Ce qu’on ne traite pas maintenant
```

> Une branche `explore/*` est soit active, soit documentée puis supprimée.

---
## 2. Repartir de `main`

```Bash
git switch main
git pull
git switch -c feature/decision-trigger-policy
```

et réimplémenter proprement ce que l'exploration m'a appris.

>[!important] C’est extrêmement important en R&D.
>
>La branche exploratoire sert à **acheter de l’information**, pas nécessairement à produire le code qui sera livré.

> Une branche `feature/*` est mergée puis supprimée.
