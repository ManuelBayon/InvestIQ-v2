Pour ton système de trading, je ne ferais donc **ni 100 % sans IA**, ni **IA qui conçoit tout pendant que tu reviews**.

Je répartirais ainsi :

- **À garder sous ton contrôle intellectuel direct** : architecture, causalité, invariants, ownership d’état, ordering des événements, replay, déterminisme, accounting/PnL, risk semantics, contrats entre sous-systèmes, critères d’acceptation et scénarios de panne.
- **À faire toi-même régulièrement sans IA** : petits composants critiques, algorithmes fondamentaux, transformations d’état, tests de propriétés, debugging conceptuel. Pas forcément tout le code, mais assez pour conserver le réflexe de construction.
- **À accélérer fortement avec l’IA** : boilerplate, génération de tests supplémentaires, refactors mécaniques, serialization, tooling, documentation, scripts, exploration d’API, variantes d’implémentation.
- **À utiliser l’IA comme adversarial reviewer** : « quels invariants ai-je oubliés ? », « donne-moi un contre-exemple », « comment casser cette hypothèse ? », « quelles transitions d’état sont ambiguës ? », « quels comportements divergent live/replay ? ».

Le point essentiel est celui-ci : **tu dois être l’auteur du modèle mental, pas nécessairement l’auteur de chaque ligne de code**.
